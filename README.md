🌿 Root Agentic OS: המוח האוטונומי של הפרויקט שלך
​Root OS אינה עוד כלי תיעוד. היא מערכת הפעלה אג'נטית (Agentic OS) המיועדת להפוך את ניהול הפרויקט לישות חיה, לומדת ואוטונומית.
​בזמן שאתה מתרכז בכתיבת הקוד, רות (Root) פועלת בצללים. היא מאזינה לכל שינוי, מנתחת את המשמעות האסטרטגית שלו, ומעדכנת את תשתית הידע של הפרויקט ללא מגע יד אדם. היא מגשרת על הפער שבין "מה שכתוב בקוד" לבין "מה שהמתכנת התכוון אליו".
​👁️ חזון המערכת: תיעוד כתוצר לוואי
​הפילוסופיה שלנו פשוטה: תיעוד לא צריך להיות מטלה, הוא צריך להיות תוצר לוואי של יצירה.
רות מבינה שמתכנתים מאבדים הקשר (Context) ככל שהפרויקט גדל. היא שם כדי לוודא ששום החלטה לא נשכחת, שום חוב טכני לא נעלם, והארכיטקטורה תמיד נשארת ברורה – גם אם לא נגעת בפרויקט חצי שנה.
​🚀 יכולות הליבה של המפלצת
​🧠 זיכרון אדפטיבי (Adaptive Survival)
​רות היא "שורדת". היא מזהה באופן אוטונומי את הסביבה שבה היא רצה:
​במחשב (PC/Mac/Linux): היא מפעילה זיכרון וקטורי מלא (Vector DB) המבוסס על ChromaDB לחיפוש סמנטי עמוק.
​בטלפון (Termux/Android): היא עוברת למצב "Lite" חסכוני במשאבים, המשתמש ב-JSON ו-Numpy כדי לשמור על מהירות שיא וסוללה, מבלי לוותר על אינטליגנציה.
​🛡️ השגחה גלובלית (Global Daemon)
​לאחר ההפעלה הראשונה, רות הופכת לשירות רקע (Service) במערכת ההפעלה שלך. היא כבר לא דורשת ממך להריץ פקודות. היא פשוט "שם", מאזינה לשינויים ב-Filesystem של כל הפרויקטים שרשמת תחתיה.
​🔍 Monster Scan
​בכניסה לפרויקט חדש, רות מבצעת סריקת עומק. היא לא רק קוראת קבצים, היא מנתחת קשרים בין מודולים, מזהה צווארי בקבוק ומייצרת "מפה מוחית" ראשונית של המערכת.
​🛠️ הנחיות התקנה
​ההתקנה מבוצעת פעם אחת בלבד והופכת את הפקודה root לזמינה מכל מקום במערכת.
​שלב 1: הורדת המערכת
​שכפל את המאגר למכשיר שלך:
git clone https://github.com/YourUser/root-os.git
cd root-os
​שלב 2: התקנה מותאמת מכשיר
​המערכת תתקין רק את מה שחיוני לסביבה שלך כדי למנוע המתנה מיותרת בקימפולים כבדים:
​למחשב אישי (גרסה מלאה):
pip install -e .[full]
​לטלפון נייד (גרסת Termux/Lite):
pip install -e .
​שלב 3: הגדרה ראשונית
​הרץ את הפקודה הבאה כדי להגדיר את מפתחות ה-AI שלך פעם אחת ולתמיד:
root
​🎮 פרוטוקול עבודה שוטפת
​רישום פרויקט חדש:
נכנסים לתיקיית קוד שאתה רוצה שרות תשמור עליה וכותבים:
root
זהו. המערכת רשמה את הפרויקט, ביצעה סריקה ראשונית, והפעילה את שירות ההשגחה ברקע.
​עבודה שוטפת:
אין צורך לכתוב יותר פקודות. רות מזהה לבד:
​שמירת קובץ -> ניתוח סמנטי מיידי.
​ביצוע Commit -> עדכון היסטוריה ורואדמאפ.
​שינוי מבני -> עדכון המניפסט ב-ROOT.md.
​📂 הארכיטקטורה: שלושת עמודי התווך
​בכל פרויקט, רות מנהלת שלושה קבצים אסטרטגיים שמהווים את ה"מוח" של המערכת:
​1. ROOT.md (המניפסט הארכיטקטוני)
​זהו המקור היחיד לאמת לגבי המצב הנוכחי של הפרויקט. הוא כולל:
​מיפוי מודולים וקשרים ביניהם.
​הגדרת טכנולוגיות בשימוש.
​תיאור זרימת הנתונים במערכת.
​2. HISTORY.md (יומן ההחלטות האסטרטגי)
​לא מדובר ב-Commit Log טכני, אלא ביומן של "למה".
​הסבר על החלטות קריטיות (למה עברנו מ-Flask ל-FastAPI?).
​הקשרים היסטוריים לשינויים גדולים.
​זיכרון ארגוני שמונע חזרה על טעויות עבר.
​3. ROADMAP.md (ניהול היעדים האוטונומי)
​רות סורקת את הקוד ומזהה משימות:
​Auto-TODO: משימות שנגזרו מתוך הערות בקוד או חוב טכני שנוצר.
​Strategic Steps: הצעות לשיפור הארכיטקטורה המבוססות על ניתוח AI.
​Priority Management: סדרי עדיפויות המשתנים בהתאם לקצב הפיתוח.
​🖥️ הדשבורד ושרת ה-Bridge
​רות כוללת שרת API מובנה (FastAPI) המאפשר תקשורת עם ממשקי Web.
ניתן לגשת לסטטוס המערכת בכתובת:
http://localhost:8000/status
​השרת מאפשר:
​שאילתות סמנטיות על הזיכרון של הפרויקט.
​הרצת פקודות טרמינל מאובטחות מרחוק.
​צפייה בניתוחים בזמן אמת של ה-Root Critic.
​🛡️ פרטיות וסינון
​Zero Cloud Leak: כל ההגדרות והמפתחות נשמרים בתיקיית הבית של המשתמש (~/.root_config) ולא בתוך הפרויקט.
​Smart Filtering: באמצעות קובץ .rootignore, ניתן להגדיר לרות בדיוק לאילו קבצים לא להתקרב (קבצי דאטה ענקיים, ספריות חיצוניות וכו').
​Local Control: בגרסאות עתידיות, תמיכה מלאה ב-Ollama תאפשר עבודה ללא אינטרנט כלל.
​Root OS - המערכת שלא רק שומרת לך על הקוד, אלא מבינה אותו.
